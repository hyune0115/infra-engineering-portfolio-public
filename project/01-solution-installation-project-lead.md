# 대규모 고객사 솔루션 신규 구축 프로젝트 리딩

## 1. 배경

### 가. 프로젝트 개요

1) 대규모 고객사를 대상으로 그룹웨어 솔루션을 신규 구축하는 프로젝트
2) 메일/그룹웨어/모바일 등 다수의 서비스 클러스터를 개발계·운영계 각각 구축해야 하는 규모로,
   설치 대상만 Worker 노드 기준 총 8식 이상, 클러스터 단위로는 6개 이상

### 나. 본인 역할

1) 설치계획 수립부터 서비스 오픈 현장 지원까지 프로젝트 전 주기를 단독으로 수행
2) 고객사 측 네트워크/인프라 담당자, L4 장비 벤더 엔지니어 등 외부 이해관계자와의 조율까지 직접 주도

## 2. 기대효과

### 가. 전 주기 단독 리딩을 통한 리스크 최소화

1) 설치계획-실행-검증-오픈까지 하나의 파이프라인으로 관리해, 담당자 교체나 인수인계로 인한
   정보 누락 리스크 없이 일관된 기준으로 프로젝트를 진행

### 나. 현장에서 발견한 문제를 근거로 한 아키텍처 의사결정

1) 설치 과정에서 직접 발견한 인프라 제약(L4 장비의 L7 미지원)을 근거로, 트레이드오프까지
   고객사에 설명해 아키텍처 전환에 대한 합의를 이끌어냄

### 다. 고가용성에 대한 정량적 검증

1) 절체 시험을 직접 설계·수행해 "장애 시 얼마나 빨리 감지되고 복구되는가"를 수치로 확보 — 이후 SLA 근거 자료로 활용 가능

### 라. 주요 의사결정 AS-IS / TO-BE

| 항목 | AS-IS | TO-BE |
|---|---|---|
| 인터넷망 SSL 처리 | 하드웨어 L4 장비 (L7 미지원) | 소프트웨어 L4/L7(Traefik) |
| 화상회의 등 host 기준 라우팅 | 불가 | Traefik으로 지원 |
| 트레이드오프 | - | 마스터 노드 트래픽 집중 — 사전에 고객사와 공유 후 반영 |

## 3. 구성도 (프로젝트 라이프사이클)

```
STEP 1  설치계획 수립
          다중 클러스터 설치 순서·일정, 볼륨/포트 기준, 사전 체크리스트 설계
  │
  ▼
STEP 2  설치 실행 및 이슈 대응
          네트워크/방화벽, 클러스터 장애, 애플리케이션 연동, DB 커넥션 등
          다수 이슈를 고객사·벤더와 직접 조율하며 해결
  │
  ▼
STEP 3  아키텍처 의사결정 주도
          L4 장비 L7 미지원 발견 → Traefik 전환 제안 및 합의
  │
  ▼
STEP 4  산출물 작성
          APP 구성도, 운영가이드, 설치 결과서 작성
  │
  ▼
STEP 5  고가용성 검증
          절체 시험 설계 및 8개 Worker 노드 대상 정량 측정
  │
  ▼
STEP 6  서비스 오픈 방문 지원
          오픈 당일 현장 방문, 최종 접속 확인 및 이슈 대응
```

## 4. 성과

1) 설치계획 수립부터 오픈 현장 지원까지 프로젝트 전 주기를 단독으로 리딩해, 정상 서비스
   오픈으로 최종 완료
2) 설치 과정에서 직접 발견한 L4 장비의 L7 미지원 문제를 근거로 아키텍처 전환(하드웨어 L4 →
   Traefik)을 제안·주도해 반영
3) 절체 시험을 직접 설계·수행해 장애 감지·복구 시간에 대한 정량적 근거를 확보하고, 노드별
   편차를 통해 추가 점검이 필요한 지점을 식별
4) 다수 이슈(네트워크, 클러스터 장애, 인증서, DB 커넥션 등)를 고객사·벤더와 직접 조율하며
   해결해, 외부 이해관계자 조율 역량을 실제 프로젝트로 증명
